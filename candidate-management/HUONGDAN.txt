1. TỔNG QUAN ĐỀ TÀI & CƠ CHẾ HOẠT ĐỘNG
--------------------------------------------------------------------------------
Đề tài yêu cầu quản lý thông tin thí sinh tham gia kỳ thi:
- Mỗi thí sinh gồm: Mã dự thi (SBD), Họ và tên, Giới tính, Ngày sinh, Quê quán.
- Hai cấu trúc dữ liệu nền tảng được kết hợp:
  1. Danh sách liên kết đơn (Linked List): Quản lý tập hợp thí sinh dạng động trong bộ nhớ RAM,
     cho phép thêm/xóa linh hoạt mà không cần cấp phát mảng cố định trước.
  2. Bảng băm dạng bảng tra (Hash Table with Chaining): Gồm 26 bucket tương ứng 26 chữ cái (A-Z).
     Khóa băm (key) là chữ cái đầu tiên của Tên chính của thí sinh (ví dụ: "Nguyen Ba Linh" -> Tên "Linh"
     -> Ký tự băm là 'L' -> bucket chỉ số 11).
     Khi cần tra cứu thí sinh theo tên, hệ thống không cần duyệt hết N thí sinh (O(N)), mà chỉ cần
     tính hàm băm O(1) để đến ngay nhóm tương ứng rồi duyệt danh sách con!

4.4. NGUYỄN HỮU CƯỜNG
- File phụ trách: Sorter.h & Sorter.cpp
- Hàm cần viết code: `void Sorter::sortByNameAZ(LinkedList &list)`
- Hướng dẫn thuật toán:
  * Yêu cầu môn học: Sắp xếp danh sách liên kết bằng con trỏ!
  * Sử dụng thuật toán Interchange Sort / Selection Sort trên DSLK:
    - Bước 1: Kiểm tra nếu `list.getHead() == nullptr` hoặc `list.getHead()->next == nullptr` thì return.
    - Bước 2: Dùng 2 con trỏ `i` và `j` lồng nhau:
              for (Node* i = list.getHead(); i != nullptr; i = i->next) {
                  for (Node* j = i->next; j != nullptr; j = j->next) {
                      // So sánh tên gọi:
                      if (i->data.getFirstName() > j->data.getFirstName()) {
                          // Hoán đổi dữ liệu data giữa 2 nút:
                          Candidate temp = i->data;
                          i->data = j->data;
                          j->data = temp;
                      }
                      // Nếu trùng tên -> so sánh cả họ tên đầy đủ:
                      else if (i->data.getFirstName() == j->data.getFirstName()) {
                          if (i->data.getHoTen() > j->data.getHoTen()) {
                              Candidate temp = i->data;
                              i->data = j->data;
                              j->data = temp;
                          }
                      }
                  }
              }
    - Bước 3: In thông báo và gọi `list.display();` để xem danh sách đã được sắp xếp tăng dần A-Z.
- Câu hỏi vấn đáp mẫu:
  * Thầy hỏi: "Độ phức tạp của thuật toán sắp xếp này là bao nhiêu? Có hoán đổi liên kết hay hoán đổi dữ liệu?"
  * Trả lời: "Dạ thưa Thầy, độ phức tạp là O(N^2) số lần so sánh. Ở đây em lựa chọn hoán đổi giá trị data
    giữa 2 nút vì cấu trúc Candidate gọn gàng, giúp code tường minh và tránh rủi ro đứt gãy con trỏ next."

- Hướng dẫn thuật toán tối ưu xác suất:
  * Đề bài yêu cầu: Phân danh sách vào n phòng thi sao cho xác suất trùng chữ cái đầu của tên trong cùng 1 phòng là ít nhất.
  * Ý tưởng thuật toán cực hay dựa trên Bảng băm:
    - Bảng băm đã nhóm sẵn tất cả thí sinh có cùng chữ cái đầu vào từng bucket (từ 'A' đến 'Z').
    - Do đó, duyệt qua từng bucket từ 0 đến 25:
      + Với mỗi nhóm chữ cái (ví dụ nhóm 'A' gồm: An, Anh, Ánh...): ta dùng kỹ thuật Round-Robin rải đều
        lần lượt từng thí sinh vào các phòng thi: phòng 0, phòng 1, phòng 2... phòng n-1 rồi quay lại 0!
      + Nhờ rải đều theo chu kỳ, các thí sinh có cùng chữ cái đầu sẽ nằm ở các phòng KHÁC NHAU,
        giúp xác suất trùng chữ cái đầu trong mỗi phòng đạt mức TỐI THIỂU!
    - Bước thực hiện:
      1. Khởi tạo mảng n phòng thi: `std::vector<LinkedList> rooms(numRooms);`
      2. Biến con trỏ phòng xoay vòng: `int curRoom = 0;`
      3. Duyệt 26 bucket của HashTable:
         for (int b = 0; b < HashTable::TABLE_SIZE; ++b) {
             const LinkedList& bucket = table.getBucket(b);
             Node* p = bucket.getHead();
             while (p != nullptr) {
                 rooms[curRoom].insertTail(p->data);
                 curRoom = (curRoom + 1) % numRooms; // Xoay vòng
                 p = p->next;
             }
         }
      4. In danh sách thí sinh từng phòng ra màn hình.

6. CÁC LỖI KINH ĐIỂN CẦN TRÁNH TRONG MÔN CTDL&GT (ĐẶC BIỆT LÚC VẤN ĐÁP)
--------------------------------------------------------------------------------
1. Lỗi Null Pointer Dereference: Luôn kiểm tra con trỏ khác `nullptr` trước khi truy cập `p->data` hoặc `p->next`.
2. Lỗi rò rỉ bộ nhớ (Memory Leak): Khi xóa một nút trên DSLK, phải gán con trỏ tạm rồi mới `delete`, tránh làm
   mất liên kết tới các nút phía sau. Lớp LinkedList đã có Destructor `~LinkedList()` giải phóng toàn bộ bộ nhớ.
3. Lỗi thứ tự nối dây con trỏ:
   Khi chèn nút mới vào giữa:
   - ĐÚNG: `newNode->next = p->next; p->next = newNode;`
   - SAI:  `p->next = newNode; newNode->next = p->next;` (sẽ tạo vòng lặp vô hạn và mất toàn bộ danh sách phía sau!).
4. Lỗi băm vượt kích thước mảng: Hàm băm `hashFunction` luôn đảm bảo chỉ số trả về nằm trong khoảng [0, 25].
